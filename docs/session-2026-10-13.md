## 3. Fix: the PSN import's 500 error

**What happened.** A PSN import (user `Barbaaz_`) answered 500. The log showed `UniqueViolation` on
`uq_games_title_platform` for the PS4 game "Digimon Story: Cyber Sleuth – Hacker's Memory".

**Cause.** The scrapers saved that game from Press Start less than a second after the import had checked
that no game of that name existed. `igdb_game_service.collection_editions` (Steam and PSN imports) and
`igdb_game_service.create` (the sell form's "add a game from IGDB") both check for a game of the same
name, then insert one. A game committed between the check and the insert made the insert fail, and the
whole import was lost. It can only happen while the scrapers run.

**Fix** (`app/services/igdb_game_service.py`). A new helper, `_added()`, adds the game inside a
savepoint. If the unique constraint fails, it uses the game that was saved in the meantime. Both places
use it.

**Tests** (`tests/test_igdb_games.py`). Two new tests save a store's game of the same name between the
check and the insert. Before the fix they failed with the site's exact error; now they pass.

## 4. Change: one kind of picture on every card

**Before.** A card showed the game's IGDB cover only for the Standard edition. Special editions showed a
store's photo of their box (square, 3D box shots, small), whole on white. 1,418 of the 3,988 catalogue
cards had a store photo: 1,015 special editions and 403 games without an IGDB cover. Next to the covers
they looked like white tiles of different shapes.

**Now** (the user's choice):

- **IGDB cover for every edition.** `card_cover` (`app/services/common.py`) no longer limits the cover
  to the Standard edition. 3,454 of 3,988 cards (87%) show an IGDB cover.
- **Edition badge.** A special edition's card shows its edition's name in a small dark badge at the
  bottom right of the cover. It shares a row with the "historical low" badge and wraps above it on a
  narrow card. The edition's own box photo is still on the game page.
- **Store photos framed.** The 534 cards without an IGDB cover show the store's photo whole, on a
  blurred, darkened copy of itself that fills the 3:4 card. Photos with a white background still show
  as a white rectangle inside the frame. The page uses its own class, `framed-photo`, because
  `common.css`'s `img.store-photo` sets a white background with `!important`.
- **Used tab.** Its cards now get the IGDB cover too (`listing_service` passes `cover_image_id`).
  Before, they always showed a cropped store photo.
- **Collection.** It uses the same covers, so its special editions now show the IGDB cover as well.

Files: `app/services/common.py`, `app/services/listing_service.py`,
`app/services/collection_service.py` (a comment), `static/pages/index.js` (`coverImage`, `coverFoot`),
`templates/index.html` (styles). Test: `tests/test_matches.py::test_every_edition_card_shows_the_igdb_cover`.

Checked with headless Edge screenshots of the "Special editions" tab. The service worker fetches static
files from the network first, so its `VERSION` didn't need to change.

## 5. Duplicate games

The catalogue has many games listed twice on the same platform under different store names: "UFC 5" /
"EA Sports UFC 5", "Octopath Traveler" / "Octopath Traveller", "ACE COMBAT 7 Skies Unknwon" /
"Ace Combat 7: Skies Unknown".

The project already handles these by hand on purpose: /admin's duplicates list
(`match_service.duplicates`) offers merge or "not a duplicate" for each pair. It has **298** pairs now:
130 from the same IGDB match, 168 from similar names. Many are different products: the Switch Lite
colours, "Shadow of Mordor" / "Shadow of War", "Pokémon Scarlet" / "Pokémon Violet", two Sims
expansions, mic packs and bundles. Merging them automatically would put prices on the wrong game.

**Decision:** review them in /admin, as the account `Barbaaz` (now an admin). No code was changed for
this.
